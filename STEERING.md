## 2. INTEGRITY PROTOCOL (NON-NEGOTIABLE — violations end the session)
2.1 "Done" is defined ONLY by the pushed repo + a green GitHub Actions run.
    Never report work without a commit SHA visible on GitHub.
2.2 Reply with RAW COMMAND OUTPUTS, not conclusions. If a step fails, say
    "NOT DONE: <verbatim error>" and stop.
2.3 Never fabricate numbers. Every reported metric must be traceable to a file
    in evals/results/ generated by code in the same run. Never hand-edit
    result files.
2.4 Measured values must come from measurement code paths only. Hardcoded
    evidence values (0.88, 3500, 0.0035, ": 8", latency*0.35) are forbidden
    in src/.
2.5 Never claim an acceptance criterion PASS unless a machine check in CI
    proves it. If it cannot be machine-checked, label it NOT VALIDATED.
2.6 Scope discipline: before any change beyond the instruction, ask: "Does
    this change any acceptance criterion or phase gate?" If not, follow the
    spec as written. If yes, ask the owner first.
2.7 Push protocol: one commit per logical fix, conventional messages, push
    after each, paste `git push` output. Never bulk-dump multiple fixes in
    one commit.
2.8 Credentials: tokens and API keys are provided via workspace secrets /
    GitHub secrets only. Never ask the owner to paste credentials in chat,
    and never write credentials into files, remote URLs, or logs.
